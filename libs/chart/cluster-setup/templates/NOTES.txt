Watch the operator come up and enrol:

  kubectl -n {{ .Release.Namespace }} rollout status deploy/hangar-operator

Enrolling does not move the cluster's `phase`. Phase is declared state with one
writer — the API — and `reachable` on the sync state already answers liveness, so
promoting on a handshake would give the row two writers. A cluster therefore stays
`pending` however healthy its stream is, until somebody says otherwise:

  PATCH /v1/clusters/{{ .Values.cluster.id }}   {"phase": "active"}

Do it, because nothing serves from a cluster that is not `active`: endpoints
resolve only on a phase that may serve, so a `pending` cluster is absent from the
gateway's routing table and its models answer as though they were nowhere.

{{- if .Values.monitoring.enabled }}

ℹ  Telemetry egress is on. Confirm the agent is actually sending, because a
   scraping-but-not-writing agent looks identical to a healthy one from outside:

     kubectl -n {{ .Release.Namespace }} logs deploy/hangar-metrics-agent | grep -i 'remote_write\|401\|403'

   Then confirm the plane's store has the label before adding this cluster to
   HANGAR_METRICS_SOURCES — an entry added early replaces an honest "no metrics

     /api/v1/label/cluster/values
{{- else }}

⚠  No telemetry leaves this cluster (monitoring.enabled=false). The operator can
   still read DCGM for device identity, but every metrics panel for this cluster
   in the console will be empty. Set monitoring.enabled=true with
   monitoring.remoteWrite.url, cluster.region and the basicAuth credential.
